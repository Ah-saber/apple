# v0.6：九帧联合去噪前端 SS928 部署、耗时与质量报告

日期：2026-09-26（Asia/Shanghai）。实验：EXP-20260926-007。状态：默认两模型已转换、实板运行、计时并复核；**研究版，未通过 16.7 ms / 独立画质 / 在线长稳验收**。

## 1. 结论

这次有明确的板端速度进步。1280×1024 九帧输入、3840×3072 输出，两场景各 50 次预热＋600 次正式采样：

| 场景 | 上一已测 v0.5 R4 同步模型 ms | 本次 v0.6 R2 同步模型 ms | 本次 P95 ms | 耗时下降 | 加速比 |
|---|---:|---:|---:|---:|---:|
| 普通夜间 joint8 | 216.079 | 105.450 | 108.559 | 51.20% | 2.049× |
| 特殊夜间 joint12 | 216.137 | 106.594 | 109.666 | 50.68% | 2.028× |

主要收益来自**替换轨迹、门控、去噪和输入重排的旧前端**，不是把它们移到 ARM 或从计时中剔除。最终图 AICPU 任务数均为 0。全图仍比 16.7 ms 慢约 6.3～6.4 倍。

不是下载即能直接转换：原图常量 bias 别名导致编译失败；展开常量后能运行，但 Resize 回退 CPU。复用真实 R4 的兼容参考分支并适配新输出顺序后解决回退，形成最终 R2。所有失败、中间候选、日志、输出和哈希均保留。

相对**各自同版本 PC 参考**的部署一致性比历史记录改善，但不能据此声称对真实 GT 的画质提高。本轮只有普通/特殊各一个独立于校准的质量输入；特殊场景从本轮混合图改为全 NPU 后，MAE 由 2.811 增至 4.100 灰度级，仍有速度—数值精度权衡。

## 3. 网络改了什么

输入仍为 FP32 `nine_raw[1,9,1024,1280]`＋FP32 `reference_thumb[1,1,64,64]`。新的前端：

1. 保留最新帧；前六帧求均值，九帧与均值相减并乘 64；与最新帧拼成 10 通道。源码要求此处 FP32；板端 mode6 是编译量化执行，不能仅凭源码 Cast 认定内部全精度保持。
2. `Conv 10→8, 6×6, stride2, pad2`＋ReLU，得到半分辨率特征。
3. `Conv 8→w, 3×3, stride2, pad1`＋ReLU，得到四分之一分辨率；普通 w=8，特殊 w=12。
4. 四个 `Conv w→w, 5×5` 残差块，每块 `x + ReLU(Conv(x))×0.25`。
5. `ConvTranspose w→4, 4×4, stride2, pad1`，加半分辨率 `1×1 skip`，乘 0.025，再加当前帧的 pixel-unshuffle2，输出 `[1,4,512,640]`。
6. 保留冻结 Head、4 个 Body、参考缩图分支、Tail、输出卷积；6× PixelShuffle 得到整图。默认先对 FP16 packed 做重排，再转 FP32、clip[0,1]、乘255，最后板端 ARM 转 uint8。

这是训练得到的近似，**不是旧 33 种运动轨迹规则的等价代数替换**。弱目标和分布外运动需要独立验证。普通选训练500步，特殊1000步；本轮没有重训或手改学习权重。

## 4. 编译、兼容性及数值回归

设备 SS928V100；SVP_NPU 2.0.2.1，SDK 2.0.2.2。转换采用 SS928V100 / V101 / compile_mode=6（activation16、weight8）/ `gelu_high_precision_mode=1` / `online_model_type=3`，FP32 输入、FP32 输出。完整参数在每个 `atc_*/command.txt`。

| 问题或新算子 | 实测事实 | 处理/限制 |
|---|---|---|
| `/front/skip/Conv` bias | 原图错误 `Layer[/front/skip/Conv]'s bias is online, not support` | 普通 Identity_50、特殊 Identity_29 将已有 initializer 别名传给 bias；将别名物化成 initializer。两张完整 PC 输出逐位相同 |
| 普通 `/Resize`～`/Resize_3`、特殊 `/Resize` | R1 编译成功，但 CPU 回退4/1 | 真实 R4 的固定插值兼容图接入新前端，R2 编译产物和实际运行均 AICPU=0 |
| 新 6×6 stride2 Conv | 编译映射 NPU Convolution，板端成功 | 与 Concat、下一层 down Conv 融合计时，不能分摊为两层各自时间 |
| 新 4×4 stride2 ConvTranspose | 编译映射 NPU Deconvolution，板端成功 | 普通0.521 / 特殊0.975 ms，非当前主要瓶颈 |
| 6× PixelShuffle | 仍映射6个 NPU Deconvolution＋Concat | 改到 FP16 重排没有消除拆分；第一个与 Tail 等融合 |
| 量化极小权重告警 | 普通 R1 `/pyramid.2/pyramid.2.3/Conv` 存在约5.58e-8的小参数，低于约5.96e-8阈值 | 保存告警；没有证据将整幅输出偏差归因于这一个参数 |

R1独立 profile：普通 NPU102.425 ms＋CPU整段367.051 ms＋未归属1.102 ms≈同步470.578 ms；特殊 NPU105.246＋CPU整段271.967＋未归属1.054≈378.266 ms。CPU整段已含CPU算子，不重复相加。普通最大CPU Resize算子329.904 ms，特殊266.631 ms。

R2 对原始新图的 PC 完整灰度回归：普通浮点 MAE `1.0793e-5`、特殊 `9.3775e-6`；最大均0.124512灰度级。转 uint8 后最多差1级，普通151个、特殊97个像素改变（总11,796,480）。固定插值的运算顺序误差很小但非逐位一致。源码参考与本地 ORT 本身也有约0.046级平均差异，因此同时保留“对源码”和“对自身ORT”的评分，见[PC回归](../../records/iterations/v0.6/pc-regression.json)。

**支持的结论是：这两张最终具体图在当前SDK/参数下可全NPU运行，不是SS928支持任意形状的所有算子，也不是量化数值无误差。** [详细兼容记录](../06_issues/ISSUE-009-packed-front-compatibility-and-fidelity.md)。

对齐“大前端＋Head/Body”的编译任务边界：普通154.791→45.454 ms，特殊155.918→48.607 ms。对齐“融合尾部起至最终输出”：普通48.108→45.998 ms，特殊48.605→48.157 ms。**约一百多毫秒的收益集中在前端，输出路径没有相近量级的改善。** 融合边界发生变化，不能进一步将差值净拆到单层。

仍然慢的原因及下一轮优先级：

1. **输出路径优先**：尾部联合区至报告仍46～48ms，已超过16.7ms。剩余五个重排本身约27ms；只压缩Body或给前端再减通道，不足以达标。可试FP16整图输出及packed接口，但本轮未板测；packed只改排布不减少元素数，若移ARM重排需把其开销计入总算法。
2. **减少无效布局/DDR往返**：前端pack/layout12～13ms、均值差分7ms、NPU输入格式转换6ms，明显大于前端4个学习残差块的3～5ms。应尝试保持统一布局、固定切片与重排融合；是否收益需要新图profile，不能把这些任务改名为“预处理”后从总时间消失。
3. **stem/down融合区约18.9ms**：两场景几乎相同，优先研究更早降采样、等价折叠/融合或训练替代，而非继续仅缩减四分之一尺度残差宽度。这里没有单独stem/down计时，不能断言其中哪一层独占18.9ms。
4. **主机流水线约81～82ms**：输入拷贝、输出拷贝和8-bit转换很重。考虑直接写入输入缓存、输出逐行转换与拷贝融合，保留同步/cache正确性。此类优化可以改善全链路，但不算NPU模型本身提速，未经测试不承诺收益。
5. **量化精度与速度一起看**：扩大独立训练校准覆盖，定位参考分支和6×相位误差；特殊R2虽然快，偏暗较R1明显，不能只按时长选最终交付。
