# v0.6 板端报告驱动的模型侧候选

本目录为增量包。保留并依赖同仓库 `../ss928-night-nine-packed-front-20260926/` 的冻结权重、运行代码、输入、校准集和预处理；单独下载本目录不足以复现源码。原版本不修改。本轮没有重新训练。

目标：SS928 整模型同步推理 ≤16.7 ms，九帧处理、整图参考和完整输出均在模型内。RAW 读取、预处理、主机与 NPU 交互、ARM 显示转换不计入目标。

当前可证明：源码及工具对照通过，GPU 测速完成，完整视频已保存。新候选的 SS928 编译、量化、耗时尚未验证，不能称为已提速或已达标。

## 报告依据

部署报告中，v0.6 最终 R2 同步实测普通 105.450 ms、特殊 106.594 ms，相对 v0.5 约减少一半。独立逐任务分析得到 NPU 103.090 / 107.991 ms，不能与 600 次同步统计混算。

- 剩余五个输出反卷积共 26.960 / 27.089 ms；输出尾部到报告格式共 45.998 / 48.157 ms。
- 当前帧取出、两倍空间打包及布局变换共 12.230 / 13.298 ms。
- 拼接、首个卷积与降采样的合并任务约 18.9 ms，报告不足以分配其中各算子的耗时。
- 输出尾部即使全部消除，剩余仍约 57.1 / 59.8 ms。一次输出改写无法保证达到 16.7 ms。

原报告保存于 `evidence/BOARD_REPORT_v06.md`。实际 R2 模型和逐任务原表本地不可访问，工具提供给部署端直接处理其已有文件。

## 候选及实际 GPU 耗时

RTX5090，FP32 九帧和缩略图输入，FP32 `[1,1,3072,3840]` 灰度输出；30 次预热、三轮各 200 次，关闭 TF32，编译执行。范围为整模型 GPU 执行，不含编译、读写和传输。

| 候选 | 普通 ms | 特殊 ms | 修改 |
|---|---:|---:|---|
| 同轮当前 v0.6 | 0.425404 | 0.432329 | 对照 |
| `dither_one` | 0.523640 | 0.521960 | 输出卷积 36→4，固定六步长反卷积恢复整图，加入固定舍入补偿 |
| `dither_two` | 0.523340 | 0.521377 | 同上，采用两倍重排加三步长固定反卷积 |
| `dither_fixed` | 0.584964 | 0.584792 | 同上，再以固定卷积替代当前帧空间打包 |

新输出候选 GPU 变慢。它们针对 SS928 报告中的分解与布局任务；新映射是否更快必须上板确认。完整逐次数据在 `evidence/mean_raw_gpu_timing.json`。编译执行与源码每个测试向量平均差约 0.038–0.050 灰度级，最大约 0.43–0.45，当前对照也有差异；下面的完整画质和参考输出使用源码执行。

等价改写的另一轮对照：普通／特殊当前 0.432390／0.430712 ms；两级 2→3 为 0.447503／0.435136，3→2 为 0.453388／0.438006，固定空间打包为 0.505034／0.489247，固定打包加 2→3 为 0.512232／0.490319。均未改善 GPU 耗时；源码全尺寸测试向量与原版逐像素一致。见 `evidence/gpu_and_source_verification.json`。

## 输出方案和画质证据

每个 RAW 像素原本对应输出的九个子像素。将最后卷积的九组权重和偏置平均，得到四通道头，再在模型内恢复三倍完整画面。这会改变三倍输出纹理及裁剪顺序，属于近似修改。

直接重复的试验使亮度误差波动增加约 6–9%、对比度误差波动增加约 7–14%，未选用。当前方案加入固定 3×3 舍入补偿，范围为 −4/9 至 +4/9 灰度级，每帧使用相同空间排列，以保留显示转 8 位后九像素平均的不足一档灰度变化。没有加入随帧变化的随机量，不能据此保证 SS928 量化后也相同。

源码普通 60 帧、特殊 120 帧，按原评估区和逐帧 GT 计算，显示输出先取整，再按三倍面积平均对齐 RAW/GT：

| 指标变化 | 普通 | 特殊 |
|---|---:|---:|
| PSNR | −0.002491 dB | +0.002922 dB |
| 静态误差时间波动 | −0.1675% | −0.0392% |
| 亮度误差时间波动 | +0.0476% | −0.2171% |
| 局部对比度误差时间波动 | +0.6062% | +0.5031% |
| 弱变化区平均绝对误差 | +0.0144% | +0.1069% |

普通局部对比度波动由 0.695724→0.699941 灰度级；特殊由 1.100160→1.105695。两个已记录弱目标窗口的响应一降一升，详见 `evidence/mean_raw_dither_weak_target_audit.json`。没有目标检测标注，弱变化区指标不能证明检测能力不变。

普通评估区 `[2,0,1020,1278]`；特殊评估区 `[2,1088,1020,192]`。视频四幅均显示完整传感器范围：RAW、GT、当前 v0.6 源码、新候选。三倍预测缩回 RAW 尺度后展示，视频 5120×1080、12 fps、60/120 帧，无局部裁剪。缺少真实三倍 GT，指标不能证明三倍输出细节等价。这些测试序列已经用于本轮方案判断，不属于独立盲测。

## 部署端直接改写已有 R2

在已有依赖的环境使用。本工具不安装依赖，需要 NumPy 和 ONNX。每个场景分别执行，下例以普通夜间为例。始终以原始 R2 作为对照，保存文件和校验值。

```bash
# 等价输出重排，卷积权重及偏置同步换序
python tools/rewrite_native_r2.py --input ordinary_native_r2.onnx --output ordinary_two_three.onnx --output-shuffle two_three
# 等价固定空间打包，单独观察布局收益
python tools/rewrite_native_r2.py --input ordinary_native_r2.onnx --output ordinary_fixed_pack.onnx --fixed-pack
# 近似输出候选，保留实际 R2 的主干与整图参考兼容处理
python tools/rewrite_mean_raw.py --input ordinary_native_r2.onnx --output ordinary_dither_one.onnx
# 六步长反卷积无法编译时的结构对照
python tools/rewrite_mean_raw.py --input ordinary_native_r2.onnx --output ordinary_dither_two.onnx --two-stage
# 前两项单独测得收益后再测组合
python tools/rewrite_mean_raw.py --input ordinary_fixed_pack.onnx --output ordinary_dither_fixed.onnx
```

工具先展开初始化常量的 Identity 别名，保留权重数值，针对报告已确认的偏置加载问题。检查输出卷积、灰度裁剪与缩放、静态尺寸以及额外消费者；不匹配时明确报错。若文件已把六倍重排分解为反卷积，则需部署端使用分解前的 R2 ONNX，不能直接套用工具。

独立 CPU ONNX 对照执行验证两类模型的各项改写：等价工具与原图逐像素一致；近似工具与独立导出的同方案源码图逐像素一致。测试包括单输出通道下两种等价排列、组合固定打包及拒绝错误裁剪/额外输出；尺寸为 `[1,9,32,48]`、完整输出 `[1,1,96,144]`。这是源码控制图验证，未使用实际 R2 或 SS928。

`onnx/` 是全尺寸源码导出图，仅默认 FP32 接口。它们没有实际 R2 的厂家兼容改写；直接编译可能重现整图参考 Resize 的 CPU 回落。部署端优先改写已有 R2，随后用其既有流程编译，保留全部兼容处理。

编译沿用 v0.6 的 SDK、compile_mode=6、16 位激活/8 位权重和原始独立训练区校准样本；FP32 接口不代表内部 FP32。固定补偿权重约 0.111–0.444 灰度单位，其量化保留情况需实测。先分别检查编译成功、CPU 回落为零、匹配的 PC 输出误差，再测 50 次预热/600 次同步和逐任务耗时。原 v0.6 普通偏亮、特殊偏暗仅各一个样本，当前未盲目加入标量亮度修正。

部署端无需传回模型文件即可继续；返回新方案整模型耗时、CPU 回落数量、输出重排/固定反卷积/布局任务耗时，以及整图输出偏差和视频检查结果，即可支持下一轮取舍。需要新上板信息的原因是厂家映射、量化和内存布局成本无法由 GPU 数据判断。
