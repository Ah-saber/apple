# SS928 九帧模型 v0.10：板端 v0.9 结果后的输出量化诊断

更新：2026-09-28。目标仍是普通重度、特殊夜间两套九帧 1024×1280 输入模型，在模型内部生成完整 3072×3840 灰度图，纯 NPU 推理均值和 P95 均不超过 16.7 毫秒，并保留去噪、连续帧亮度与局部对比度、弱结构响应。RAW 读取及主机/NPU 交互不计入纯 NPU 时间。

## 已有板端事实

部署端 v0.9 报告的可用 FP16 `rows32` 同步均值/P95：普通 28.782/30.052 毫秒，特殊夜间 30.389/31.557 毫秒。相对冻结 v0.8 C11 的均值差仅 −0.027/−0.185 毫秒，尚无稳定提速证据。`rows32_refpad16_u8` 的 `/output/Round` 回退 CPU，两帧诊断同步约 573.689/598.190 毫秒。`raw6` 在普通板测预热时出现硬件 execute500004，禁止在业务板上自动复试。

v0.9 C01 短 profile 的纯 NPU 任务组约为普通 6.502 前端主体 + 5.673 参考前段 + 3.238 参考尾端 + 8.925 整图输出布局 + 3.623 Report = 27.961 毫秒；特殊夜间对应 9.170 + 4.914 + 2.915 + 8.907 + 3.746 = 29.651 毫秒。因此仅改变输出契约不足以保证 16.7 毫秒，后续还需改参考和夜间前端，并以实际任务时间判断。

## 本版可测图

`source_onnx/{ordinary,special}_rows32_quantizelinear_u8.onnx` 以冻结 v0.9 `rows32` 完整 FP16 图为主体，仅在模型末端新增 `Cast(FP16→FP32)` 和 `QuantizeLinear(scale=1,zero=0,uint8)`。它仍在图内产生完整三倍输出。采用标准的舍入到最近偶数以及 0～255 饱和语义，替代 v0.9 `Round→Clip→Cast`；图中 `Round` 节点数为 0，`QuantizeLinear` 为 1，输出类型为 UINT8。新增的整图 FP32 转换可能造成额外物化与时间，板端是否支持该算子及能否真正省时均未验证。

ONNX Runtime 同后端验证：普通第 20 帧与特殊夜间第 60 帧的完整 3072×3840 UINT8 输出，和 v0.9 `rows32_u8` 各自逐字节相同；各自 64×96 小图也逐字节相同。与 PyTorch 源输出直接比较时，普通/特殊有 580095/549630 个像素差 1 级，来自执行后端的半精度数值差，不能据此声称与板端逐字节相同。真实 GT、板端视觉偏差和时序问题沿用 v0.9 待验状态，本版没有新的质量改善权重。

## 已筛除的输出布局

`direct_g1/g2/g4/g8/g16` 用单个反卷积直接生成完整输出，消去块输出后的 Concat/Transpose/Reshape。相同 FP16 特征及完整模型均与 `rows32` 逐像素一致。普通 GPU 原生执行均值基线 0.523 毫秒，各直接布局分别 0.705/1.098/1.089/0.697/0.711 毫秒；特殊夜间基线 0.508 毫秒，分别 0.692/1.083/1.076/0.683/0.698 毫秒。此比较只用于源端筛选，未生成这些布局的板测主候选图，也不能作为板端耗时预测。完整数据见 `evidence/*_complete.json`。

## 下一次板端部署的最小判断

1. 先恢复测试主机空间；v0.9 报告称 C 盘仅约 0.7 MiB 可用。保留所有旧实验和业务文件。
2. 用部署端现有 R1 双线性兼容改写及相同 SDK、`compile_mode=6` 分别转换普通、特殊夜间新图。兼容改写应保留末端 `Cast→QuantizeLinear`，核对转换前后同帧输出。
3. 先查编译任务分配。若 `QuantizeLinear` 或其前置 Cast 落 CPU，停止该候选的长时间测量；记录 CPU 节点及往返内存任务。若 AICPU=0，再在同一条件下重测 v0.9 `rows32` 与新图，分别记录纯 NPU 均值/P95、同步模型均值/P95、逐任务 Report/输出阶段耗时和显存读写。不得把 UINT8 的字节数直接当作节省的毫秒数。
4. 对领先者比较同帧完整输出与对应 PC 图、字节灰度偏差及相位图；仅在时间和精度都合格后补普通 60 帧、特殊 120 帧整图视频与弱结构连续帧审查。

若量化图仍回退 CPU 或变慢，`rows32` 保持可用基线。下一轮重点转向参考末段的纵向布局任务（普通约 1.931 毫秒）与特殊夜间前端 9.170 毫秒联合任务；具体融合策略需新的板端算子归属和中间输出证据。目前没有达到 16.7 毫秒的模型，也没有证明本版提速。
