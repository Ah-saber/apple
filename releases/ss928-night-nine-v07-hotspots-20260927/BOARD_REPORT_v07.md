# v0.7：SS928 统计前端、行分组与半精度接口实板报告

实验：EXP-20260927-008；日期：2026-09-27；输入 1280×1024、九帧、batch1，参考缩略图 64×64；完整输出 3840×3072、全部36相位。

结论：**新统计前端有效；文档推荐的rows16＋NHWC FP16组合不适合作为当前SS928默认方案。** 本轮最快的是 `front_f32`：普通/特殊同步模型 **81.228/80.351ms**，比冻结v0.6下降 **22.97%/24.62%**；独立NPU **80.826/80.415ms**。保持FP32接口时已预处理输入→8bit内存为 **164.450/163.463ms**，不含RAW预处理。

加rows16后为90.099/89.260ms；推荐半精度组合为100.936/100.005ms，且相位偏差、SSIM明显退化。四个浮点候选经有限兼容修复后均无CPU回退；直接uint8候选两场景都编译失败。**16.7ms、独立GT画质、完整RAW链路与长稳均未验收。** 本报告逐项回答README/RESULTS/HANDOFF中的问题，并保留负结果。

## 2. 测量口径与可比性

## 4. 结构与逐模块时间：回答交接文档

### 4.1 新的三个前端卷积

原路径中的当前帧pack2、全分辨率时间差分、6×6s2 stem、3×3s2 down、四个5×5残差、前端恢复反卷积和skip已由新前端替代；不是把旧节点换名字。

1. 固定统计Conv：9→12，2×2、stride2，生成当前/前六帧/最近三帧各四个空间相位，输出512×640。前六权重前五项120/727、末项127/727；最近三权重123/373、123/373、127/373，理论和为1。
2. 将两组差分放大64倍，与当前四相位拼成12通道；学习Conv12→8（普通）或12（特殊），3×3、ReLU。
3. 学习Conv8/12→4，3×3；校正×0.025加回当前相位，再进入冻结Head、四Body、参考融合、Tail及36相位输出。

新前端全部九帧参与，但感受野与旧前端不同，是重训练的近似替代，不是算法等价图优化。编译后第一个固定卷积可单独计时，后两个学习卷积与Concat、前端加法、Head及四Body融合，不能编造每层独立毫秒数。

### 4.2 行分组、六个输出反卷积与恢复

rows16把 `[1,36,512,640]` 的完整行分组为 `[1,576,32,640]`，DepthToSpace6产生 `[1,16,192,3840]`，再恢复 `[1,1,3072,3840]`。未裁图、未平均相位、未把重排放到ARM。

两场景编译图仍有**六个Deconvolution**，并仍有分组转置/reshape任务，不能说分组被完全撤销，也不能说改为一个高效shuffle。front_f32的第一个反卷积与参考末段/Tail/输出Conv融合，无法单独测出六个总和；只能列“联合任务＋剩余五个”。rows/primary可独立列六个之和。最终reshape有融合，按联合任务报告而不人为拆时间。

两场景各自的front_f32与rows_f32保存的完整FP32输出及uint8输出哈希相同，PC同样一致。因此在这两个输入上，rows是数值无变化、性能退步的候选；不推广为所有输入的量化等价性证明。布局信息证明实际边界开销，尚无足够证据把全部输出瓶颈归因于内部C16填充。

### 4.3 NHWC/FP16、Report与真实缓冲区

FP32九帧实际输入47,185,920字节，stride5120；声明NHWC FP16逻辑数据23,592,960字节，但SDK缓冲区41,943,040字节、stride32，每个位置的9×2=18字节被填充。运行器按实际stride装填，不能连续复制逻辑文件就当输入正确。还有显式NHWC→NCHW模型内Transpose，其成本在NPU表中单列。

缩略图保持FP32 16,384字节、stride256。完整FP32输出47,185,920字节、stride15360；FP16输出23,592,960字节、stride7680。输出名称虽沿用 `display_uint8`，真实类型由OM和运行时确认是FP32/FP16。半精度输出确实减半，但整体收益必须扣除新入口、转置、分组、缩放等开销。primary末尾Report与拼接/恢复融合，不能把整个任务都叫Report。

在ARM侧，FP32输入是9×1024次宽行拷贝；NHWC候选是1024×1280次18字节小块装填到32字节stride。普通输入拷贝从21.805ms增至45.620ms，虽输出拷贝从22.292降至11.132ms，仍不能抵消输入装填与模型开销。这个装填计时已包含；PC预先执行的NCHW→NHWC/FP16转换却不包含，不能把197ms左右的结果叫完整RAW链路。运行器没有专门优化小块装填，仍有工程优化空间，不把该实现的ARM开销当成芯片不可降低的下限。

### 4.4 参考激活、算子支持与修复

参考替换把普通5个/特殊2个Erf激活换为重训的Sigmoid×输入，编译为5个/2个Swish，AICPU仍为0。总NPU任务从101→77（普通）、44→38（特殊）；原始编译图算子数从138→123、63→57。任务数与图算子数不是同一个指标。

参考独立区间由5.968→5.372ms、5.384→4.764ms；但600次整模型均值只由100.936→100.781ms、100.005→99.872ms，约0.15%/0.13%，不足以在本轮非随机、非独占条件下声称稳健整模型加速。独立profile总和普通还从100.907变为102.063ms、特殊从100.180变为98.493ms；与600次不是同一批样本，不能挑其中较好的值作主成绩。第5节显示它也有明显的部署精度取舍，暂不推荐替换默认参考分支。

四个可运行候选的OM、运行时和profiler均确认AICPU=0；是**本轮采用兼容改写后路径无CPU回退**，不是原始源码图所有算子原生兼容。本轮遵照README接入已有R2 Resize处理，没有重新证明直接源码ONNX编译零回退。

两项交接工具修复：缩放工具假定Clip在shuffle后，与实际R2不符；参考替换工具把R2固定插值Conv误计为学习Conv。分别做了有界拓扑/参数匹配修复，原交付文件不变。完整两帧PC回归：FP32图对对应源码最大浮点差约0.125灰度，字节最大1级、仅普通118/特殊106个像素不同；primary因半精度运算顺序变化，平均浮点差约0.0193/0.0231灰度，字节最多1级，约22.6万/27.1万像素舍入不同。不是逐位一致。PC原源码ORT与包内GPU参考也约有0.05灰度平均差、字节最多1级；远小于下文板端误差，但仍保留不同参考口径。

字节候选两场景均失败：`Round_0`被分到CPU段，随后 `display_uint8_report_1_0` 报 `Aicpu only support output fp32!`。没有可用OM或有效时间。保留浮点输出＋ARM单独计时的8bit转换，未修改固件/系统库绕过失败。详见[ISSUE-010](../06_issues/ISSUE-010-system-speed-compatibility-and-fidelity.md)。

判断：

- **front_f32：速度提高，精度表现混合。** 普通平均偏亮从约+1.97降至+0.46级，MAE约2.96→2.72，一致性PSNR约+0.85dB；特殊MAE约4.10→4.38、偏暗约−4.04→−4.33，一致性PSNR约−0.54dB，虽然SSIM略升。相位范围仍约4.29/5.37级，未消除。
- **primary：不能只看均值误差。** 特殊MAE较front略小，但SSIM从0.975698降至0.881875、相位范围5.367→12.373级；普通也从0.979449降至0.933223、相位范围4.288→8.309级。交付GPU参考得到相近结论，不能归咎于本地PC实现的微小差别。该组合存在更强的相位依赖误差，不建议默认部署。

上述半精度组合同时改变入口布局/精度、缩放位置和输出类型，行分组对照仅排除了在这两帧上的rows数值影响；还不能把误差增长唯一归因于FP16本身或某个单算子。

定义：完整3072×3840输出，灰度0–255；MAE与bias为灰度级；bias=板端−同版本PC。PSNR使用data_range255，SSIM为skimage0.22.0默认均匀7×7窗、sample covariance；6×6相位范围是36个位置类别的平均偏差最大−最小，不是检测召回率或频谱幅度。统计和全部36相位数值在复核JSON中。

每个模型使用**对应的自己的PC图/新参考权重**，没有拿旧模型目标图作为新模型真值。前端/行分组/参考候选使用本地源码ORT参考；primary另外对照交付GPU参考。v0.6历史使用其自带参考。因此跨版一致性变化说明部署偏差的变化，不能直接换算成对GT的精度增益。

固定统计卷积的系数和为1、假设量化器模拟稳定，不等于真实SDK统计量化已无直流误差。转换日志还有前端Add窄缩放及参考窄范围警告；`alpha[0.000000]`是格式化值，不证明真实参数恰为零。没有逐层数值探针，无法把所有偏亮/偏暗唯一归因于统计Conv。四个校准向量覆盖不足仍需扩展。

### 5.3 完整视频和弱目标问题能否回答？

本轮能回答两张完整板端输出的部署偏差，**不能给出板端完整60/120帧时序画质验收**。交付依赖只提供普通frame20、特殊frame60与校准向量，没有对应完整连续RAW＋原始GT张量。本机原SDK测试数据为其他MP4等素材，未找到可确认与这两个交付序列匹配的原始GT；不能把压缩对照视频截帧当GT，也不能重复同一帧伪造时序样本。

## 6. 瓶颈、16.7ms差距与下一步建议

本轮front_f32的同步均值仍是16.7ms的约4.86/4.81倍，还需减少约79%的模型时间。逐任务显示普通/特殊：

| 关键区间 | 普通 ms / 占NPU | 特殊 ms / 占NPU |
|---|---:|---:|
| 参考末段＋Tail＋输出Conv＋全部重排/缩放/Report | 47.370 / 58.61% | 48.216 / 59.96% |
| 固定统计Conv | 16.967 / 20.99% | 16.943 / 21.07% |
| 两个学习前端Conv＋Head＋四Body融合 | 3.495 / 4.32% | 3.552 / 4.42% |

可比的“入口后前端至Head/Body”联合区间由v0.6的45.454/48.607ms降到21.965/21.908ms，说明新前端确实改善了真实热点。相反，输出大区间仍占约六成，是下一阶段必须处理的瓶颈；不是继续删Body就能解决。

仅作当前任务时间的乐观减法：即便整个前端至Head/Body成本变为零，仍约58.861/58.506ms；即便整个输出大区间变为零，仍约33.456/32.199ms。两者都是“不可能只修一处达标”的证据，不是可实现新网络的预测（改图后融合/访存会变）。固定统计卷积单项本身已约17ms，也说明只削减参考激活等小任务不够。

建议按以下可验证顺序推进，不把假设当收益：

1. **保留front_f32为本轮速度研究起点，撤回默认启用rows16/NHWC的假设。** 下一步单独测试NCHW FP16输入、保持旧shuffle只改FP16输出、只前移缩放；当前primary同时改多项，不能唯一归因于一个dtype。
2. **优先替换输出重排的编译映射，而非先减Body。** 保留36相位和完整输出，设计最小完整尺寸微基准测试SDK原生可高效映射的重排/卷积路径；训练侧可考虑蒸馏输出投影与原生上采样联合设计，但必须带量化/弱目标验证。已在GPU变慢的学习反卷积不能宣称NPU一定慢，也不能未经板测宣称更快。
3. **固定统计Conv是另一核心目标。** 可尝试contrast直接差分、九帧时间累积与空间pack的融合、利用流式环形缓冲增量统计。当前平衡系数不是简单等权均值，递推需严格处理不同时间位置权重和场景切换；均须验证精度。若移到ARM/IVE，应测全分辨率访存、排布、同步及额外拷贝，不是免费预处理；内存链总时间必须与原边界并列。
4. **改进外围内存链，但独立列成绩。** 合并输出stride拷贝与NEON舍入，减少完整FP32/FP16中间缓冲；缓存/零拷贝仅在业务数据所有权与SDK一致性要求满足时使用。NHWC入口的小块装填和填充可能吃掉位宽收益。不能通过不更新输入、少拷贝或复用缓存使测试偏离实时流程。
5. **质量先设门槛。** 按亮度、不同6×6相位、暗/亮/低纹理/运动校准覆盖扩充训练校准集；进行同版本逐层差分或受控前缀探针定位固定统计/后端量化偏差，必要时针对实际SDK做QAT/蒸馏。禁止凭一两帧误差直接补常数bias掩盖问题。

这些是下轮实验建议，尚未实施或证明达到16.7ms。更改完整输出/将图内处理排除目标属于验收口径变化，需要明确记录，不能用新的较小子图时间替代完整模型时间。
