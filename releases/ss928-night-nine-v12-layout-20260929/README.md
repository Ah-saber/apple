# SS928 九帧模型 v0.12：输出布局与参考支路联合筛选

日期：2026-09-29。目标是普通与特殊夜间模型在 SS928 上完成九帧 1024×1280 输入到图内完整 3072×3840 灰度输出，使**纯 NPU 同步均值及 P95 均低于 20 ms，并争取均不超过 16.7 ms**。RAW 读取、主机数据交互和文件写入不计入该指标。当前没有 v0.12 板端计时，不能宣称达到 20 ms 或 16.7 ms。

## 板端起点与需要削减的时间

部署端 `REPORT-v0.10-output4-deployment.md` 的 v0.11 安全 R2 图，同一次启动按 50 次预热、600 次同步测量：普通均值/P95 为 **26.271/27.671 ms**，夜间为 **26.944/28.695 ms**。平均任务组中，输出铺排占普通 8.851 ms、夜间 8.860 ms；输出 Report 占 3.870/3.941 ms；参考前段占 5.555/4.896 ms。Report 属于上述纯 NPU 边界。

若其余部分不变，低于 20 ms 需要普通/夜间均值分别减少至少 **6.271/6.944 ms**；达到 16.7 ms 均值需要减少 **9.571/10.244 ms**。P95 也须分别减少至少 **10.971/11.995 ms** 才达到 16.7 ms。因此本轮同时处理输出铺排、参考高分辨率放大和输出格式；各改动的实际收益须以完整图板测判断，不能相加推算。

## 已完成的模型结构实验

所有默认输入仍为普通/夜间各自的 v0.11 安全权重。普通前端保留时间 6 通道和参考 0、2 支路；夜间前端保留时间 6 通道和 20 通道首层。`source_output/` 包含以下**完整 FP16 图**，同时有 128×128 九帧输入的缩小编译图：

| 输出布局 | 结构 | 处理意见 |
| --- | --- | --- |
| `rows32` | 已验证的行分组铺排 | 安全对照；仍需部署端 R1 参考插值兼容改写 |
| `rows8/16/64/128` | 调整行分组大小 | 用输出微图先选；保持四相位及完整输出 |
| `native_deconv` | 四相位还原后一次三倍反卷积 | 先编译微图并记录实际算子/耗时 |
| `native_separable` | 四相位还原后，竖向与横向各一次三倍反卷积 | 先编译微图；源模型与安全输出逐像素相同 |
| `native_nearest` | 四相位还原后最近邻三倍插值 | 检查 CPU/AICPU 回退；已知 R1 只处理参考支路的双线性插值 |
| `direct6` | 四相位直接六倍反卷积 | 旧 `raw6` 路径有硬件 execute500004；只作为隔离板的风险诊断，业务板不自动复试 |

`output_micrographs/` 是从上述完整图抽取的输出子图；输入固定为 `[1,16,512,640]` FP16，输出仍为 `[1,1,3072,3840]` FP16。36 项普通/夜间、缩小/完整组合在同一 ONNX Runtime 后端**逐像素完全相同**；源模型固定帧各布局与 `rows32` 的 PyTorch 输出也完全相同。该等价性不等于板端数值一致或板端更快。

`source_reference/` 将参考支路的 12→16 通道线性投影移到双线性放大之后，使放大处理 12 通道。普通第 20 帧源图平均绝对差 0.0180 灰度、最大 0.25；夜间第 60 帧为 0.00890、最大 0.125。本地同一 ONNX Runtime 的完整真实帧复核中，普通/夜间逐像素相同率为 99.9876%/99.9942%。提供 `rows32`、`native_deconv`、`native_separable`、`native_nearest`、`direct6` 组合。部署端需对新插值节点核对 R1 兼容改写与 CPU/AICPU 归属。

`source_lowref/` 是夜间可选的训练后参考支路：将参考贡献在 64×64 上映射至四个相位，再放大到 512×640。只在训练上下文拟合 1200 步。120 帧独立测试中，夜间 5×5 版 PSNR **25.9169 dB**，安全版 **25.8629 dB**；弱变化区域 MAE **9.4845** 对 **9.5707** 灰度；静态误差时间标准差 **1.8826** 对 **1.8836**。亮度误差时间标准差由 0.7923 到 0.7991，局部对比度误差时间标准差由 1.1530 到 1.1538，需板端连续帧再核对。普通同法损失 0.279～0.292 dB，**已排除普通低分辨率参考作为默认候选**。夜间四栏完整画幅 120 帧视频见 `videos/special_lowref_k5_full_comparison.mp4`；视频顺序为输入 RAW、GT、安全版、候选。

`source_byte/` 和 `source_combined_cast/` 提供输出后直接 `Cast` 至 UINT8 的诊断图及逐值探针。普通/夜间源图直接 Cast 相对就近偶数舍入约有 46.0%/45.2% 像素低一级；板端上次 `AddHalfCast` 的实际偏差方向不同。必须先在板端运行 `cast_direct_probe.onnx` 和同帧完整图，检查算子实际舍入、Report 耗时及输出画质，才能选用字节图。`QuantizeLinear` 已知解析失败，不作为本轮候选。

尾部 3×3 与输出 3×3 合为一层 5×5 的实验见 `source_fused_tail/`：普通/夜间固定帧平均差约 0.131 灰度，边缘最大差 46.53/37.63 灰度，由两级填充边界造成。**该合并已排除**；文件只保留实验复现证据。

## 服务器端速度与画质边界

同轮 RTX 5090 GPU1、`test` 环境、完整输入输出、`torch.compile`、关闭 CUDA 图和 TF32：普通 `rows32` 0.3390 ms、`native_nearest` 0.2774 ms、`direct6` 0.5040 ms、`native_deconv` 2.1720 ms；夜间对应 0.3415/0.2762/0.4975/2.1566 ms。分离式图另轮普通/夜间 0.3855/0.3727 ms，同轮 `rows32` 0.3421/0.3388 ms。GPU 排名无法推断 SS928 排名；上轮 `Expand` 的 GPU 改善与板端严重退步已有实证。全部原始采样位于 `ordinary_benchmark.json`、`special_benchmark.json` 及 `separable_benchmark/`。

夜间低分辨率参考 5×5 的普通输出 `rows32` GPU 均值 0.3440 ms，同轮安全版 0.3415 ms；其目标是减少板端参考放大及尾部计算，GPU 未显示收益。板端若无收益即保留夜间安全参考。

## 一次板测的筛选顺序

1. 固定 SS928V100、SDK V2.0.2.2、SVP_NPU V2.0.2.1 B050、`compile_mode=6` 和 v0.10 的测试启动条件。先以两张 `source_output/*_rows32.onnx` 应用既有 R1 兼容改写，核对源、R1、OM 和 v0.10 安全 R2 的同帧输出及任务分组。保留原版运行证据。
2. 编译两场景完整尺寸输出微图：`rows32`、`rows8`、`rows64`、`native_deconv`、`native_separable`，另测 `native_nearest` 的 CPU/AICPU 归属。记录每图逐任务耗时、读写量、最终 Report。缩小图用于编译排错，正式速度只看完整尺寸图。`direct6` 涉及旧硬件错误，只在部署端具备隔离测试条件时尝试。
3. 选出速度与兼容性最好的两种安全布局，各自编译普通/夜间完整模型。先测基本布局，再测相应 `source_reference/` 的 12 通道放大组合。夜间若参考仍热，增加 `source_lowref/` 的 5×5 候选。各图使用同一批输入、50 次预热、至少 600 次同步执行，报告均值/P95、任务数、CPU/AICPU 归属及输出铺排、参考、Report 的任务时间。
4. Report 仍热时，先用字节小探针记录 0.5 等半整数的实际输出，再测同布局的图内字节输出。逐帧核对普通 60 帧、夜间 120 帧与各自 PC 源图及 GT，特别记录四相位偏差、弱目标、建筑细节、亮度与局部对比度稳定性。字节图带来 1 级偏差时须明确质量代价。
5. 决策门槛：普通和夜间的纯 NPU 同步**均值与 P95 均低于 20 ms**，继续争取**均不超过 16.7 ms**；所有实际可用图须完成整图输出和画质核验。若仍超时，以同一完整图的最新任务/DDR 表继续优化，避免用独立微图时间直接相减。
