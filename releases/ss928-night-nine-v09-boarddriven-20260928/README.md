# SS928 九帧模型 v0.9：依据 v0.8 板端结果继续提速

更新：2026-09-28。目标是普通重度与特殊夜间两套完整模型在 SS928 上的纯 NPU 推理均值和 P95 均不超过 16.7 毫秒，同时维持去噪、连续帧亮度与局部对比度、弱目标响应。输入仍为真实九帧 1024×1280，模型内部生成完整 3072×3840 灰度图。读取 RAW、主机与 NPU 交互及视频编码不计入此目标。

## 已知板端基线

用户提供的 v0.8 板端报告中，C11 的同步完整推理为普通 **28.809 毫秒，P95 30.170 毫秒**，特殊夜间 **30.574 毫秒，P95 32.650 毫秒**；独立纯 NPU 分别为 28.529 和 29.677 毫秒。普通场景 NPU 任务组：输入、前端与主体 6.501，参考前段 5.775，参考末段与融合尾部 3.454，整图输出与布局 9.120，Report 3.678 毫秒。特殊夜间对应为 9.171、4.772、2.777、8.970、3.987 毫秒。

v0.8 报告中的 C11 是部署端兼容改写后的 R1 模型。原始 ONNX 的 Resize 路径不能直接视为 SS928 可运行图。v0.9 目录内均为**源 ONNX**；此处没有 SS928 编译器、R1 改写源码或板端运行环境，因而没有 v0.9 的板端耗时或板端画质结论。

## 本轮主候选

`rows32_refpad16_u8` 采用三项模型内修改：

1. 将原 C11 的 16 行整图输出重排为 32 行，并固定导出形状；完整输出像素仍由模型生成。单独的 `rows32` 在源计算中与 C11 逐像素相同。
2. 参考分支将 12 通道计算补零对齐为 16 通道，学习权重保持原值；来源半精度舍入只带来极小差异。
3. 在模型末端生成完整 8 位灰度图。与 C11 的 8 位显示图比较，普通和特殊夜间的缩小 ONNX 对照均逐字节相同；完整源图连续评估见下。8 位输出是否减少 SS928 的 Report 任务和是否保持纯 NPU，需要板端验证。

同轮 GPU 事件计时，热身 30 次、3×200 次采样，输入预备排除，整套模型与完整输出均计入：

| 场景 | v0.8 C11 平均 / P95 | v0.9 主候选平均 / P95 | 同轮平均变化 |
| --- | ---: | ---: | ---: |
| 普通重度 | 0.425439 / 0.428320 毫秒 | 0.372888 / 0.376064 毫秒 | −12.35% |
| 特殊夜间 | 0.421810 / 0.424550 毫秒 | 0.369057 / 0.371554 毫秒 | −12.51% |

服务器 GPU 数值不能换算成 SS928 的 16.7 毫秒结果。两场景的完整源图质量评估：普通 60 帧 C11 与主候选均为 **27.85978 dB**；特殊夜间 120 帧均为 **25.86292 dB**。静态区域误差时间标准差、分块亮度与对比度波动也几乎相同。两处既有弱运动目标窗口的响应数值与 C11 完全相同。完整源图相对 C11 的平均差为普通 0.000049、特殊夜间 0.000043 灰度级。GT 指标在原生 RAW 网格评估；特殊场景 GT 的有效评价区为右侧 192 列。完整视频均展示全视野。

源图整图四栏连续视频，顺序为输入 RAW、GT、C11、新候选：

- `videos/ordinary_rows32_refpad16_u8_full_comparison.mp4`：普通 60 帧。
- `videos/special_rows32_refpad16_u8_full_comparison.mp4`：特殊夜间 120 帧。

每段均为 5120×1080、12 帧/秒，四栏各显示完整 1280×1024 视野。视频中的模型结果从完整 3072×3840 输出按每 3×3 单元平均到原 RAW 网格用于并排显示；中间帧原尺寸预测另存 `videos/*_native3x_frame_*.png`。播放帧率只用于观看，不表示板端速度。

## 下一次板端测试的最小矩阵

| 次序 | 两场景文件名中的 case | 所针对的 v0.8 NPU 任务 | 判断依据 |
| --- | --- | --- | --- |
| 0 | `v08_c11` | 固定基线 | 在相同编译参数下复核 C11 |
| 1 | `rows32` | 整图输出与布局约 9 毫秒 | 与 C11 源输出逐像素一致，独立判断分组收益 |
| 2 | `rows32_u8` | Report 约 3.7～4.0 毫秒 | 在 1 的基础上隔离 8 位输出影响 |
| 3 | `rows32_refpad16` | 参考分支约 4.8～5.8 毫秒 | 在 1 的基础上隔离通道对齐影响 |
| 4 | `rows32_refpad16_u8` | 输出、Report、参考分支组合 | 主候选；完整源画质已验证 |
| 5 | `raw6_rows32_refpad16_u8` | 输入、前端与主体约 6.5～9.2 毫秒 | 前端折叠诊断；特殊夜间 GPU 变慢，板端单独判定 |

以上每项请分别编译普通与特殊夜间完整图，记录编译结果、AICPU 数、**纯 NPU 均值、P95、最大值**及逐任务表。用同一帧输入比较板端与各自源 ONNX 的完整输出，记录平均绝对误差、偏差、相位误差和全图文件。领先候选另跑普通 60 帧、特殊夜间 120 帧整图视频，核查亮度漂移与闪烁。保持与 v0.8 相同的 R1 双线性与 3 倍复制兼容处理，并记录改写后完整源图的差异。

若 8 位输出编译失败或触发回退，保留 `rows32_refpad16` 的半精度整图结果。`rows32_refafter`、`rows32_meanfirst`、`rows64_u8`、`rows128_u8`、`direct48` 是额外布局和参考任务定位图，可在主矩阵之后按逐任务热点选择。`rows64/128` 的 GPU 收益不稳定；`direct48` 的大卷积核板端支持未知。

## 已试过且未选用的方向

- 短参考分支的普通场景质量从 C11 的 27.85978 降到 21.00420／21.43146 dB，不能作为通用模型。特殊夜间三层学生分支在有效 GT 区域提高到 26.59826 dB，但全图与 C11 平均相差 2.93 灰度级，GPU 比 `rows32` 慢，暂存实验视频 `videos/special_rows32_refstudent3_full_comparison.mp4`，未列入主矩阵。
- 尾部 3×3 卷积与输出 3×3 投影融合为 5×5：精确修正边缘时 GPU 从 `rows32` 的 0.37351 变为 0.41955 毫秒；忽略边缘时边框平均误差 6.82 灰度级，最大 46.56。两者均未交付为主候选。
- `raw6` 折叠前端在普通场景 GPU 有收益，特殊夜间变慢；保留为板端任务定位图。

## 文件与复现

- `source_onnx/`：普通和特殊夜间的完整模型及缩小输入的数值验证图。主矩阵命名为 `{scene}_{case}.onnx`。源模型输入类型为九帧半精度与参考缩图单精度，完整输出为 `[1,1,3072,3840]`；`_u8` 输出为 8 位，其余为半精度。
- `reference_outputs/`：真实输入帧普通第 20 帧、特殊第 60 帧的完整输出压缩文件，命名与 ONNX 对应。输入向量沿用相邻 v0.8 版本的 `test_vectors/`。
- `layout_export.json`、`extra_export.json`、`byte_export.json`、`refpad_export.json`、`wider_export.json`、`combo_export.json`：各模型形状、图算子、源差异与 SHA-256；本地 112 条导出哈希核对均通过。`small_ort_*.json` 是本地 ONNX Runtime 数值核对。
- `*_quality.json`、`*_benchmark.json`、`*_weak.json`、`*_probe.json`：完整连续帧质量、GPU 速度、弱目标和单帧边缘差异。训练输入用于短参考分支训练；测试场景仅用于评估，没有用测试 GT 选训练权重。
- `board_candidates.py`：从 v0.8 冻结模型生成候选，不覆盖原始权重。`export_board*.py`、`evaluate_board.py`、`benchmark_board.py`、`make_board_video.py` 是服务器测试入口；这些入口当前绑定既有 `5090_media#gpu` 数据目录。短参考分支权重只为失败分析保留。
