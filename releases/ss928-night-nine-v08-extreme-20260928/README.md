# SS928 九帧完整推理：速度候选与部署诊断

目标：完整推理均值和 P95 均 ≤16.7 ms。本包尚无 SS928 编译和实板结果。两次部署是推进目标，实际任务映射可能要求更多迭代。

## 当前完成项

- 已训练直接九帧前端、1/4 分辨率网络、不同宽度/深度、直接输出、联合输出、量化感知和 GT 弱变化监督；成功与失败模型均保留。共 368000 次计划内训练迭代尝试，部分混合精度训练迭代可能跳过，不能统一称为成功更新次数。各训练日志和权重记录实际预算；四个原先错误标成24000的16000步权重完整保留在预算审计目录，修正版本和真正续训版本分别保存。
- 原统计及前端计算改写为常规卷积，保留有符号输入，归一化后的负值也能处理；提供均值、整数和直接融合版本及6/7卷积核对照。24项双精度全部像素等价检查通过。
- 低分辨率网络保留4×4输入相位、32通道和单主体块，融合末卷积与输出投影。参考分支新增将缩放通道从32减至16的等价投影分拆。
- 完整输出提供像素重排、不同固定反卷积、两级2×2反卷积、三倍复制及16行分组后模型内恢复。输出仍为3072×3840。分组诊断图只用于定位布局/报告代价。
- 输入提供9帧标准布局、16槽四维/五维布局、Float32接口对照。16槽中9个真实帧、7个零槽。
- 提供66类候选×2场景×完整/小尺寸共264个模型ONNX，以及110个模块探针；每个图已通过本地完整ONNX检查。SDK兼容性均待验证。
- 14段整图连续对照视频，普通60帧、特殊夜间120帧；12帧/秒。每面板完整1024×1280，模型原生3072×3840输出另存PNG。

## 实测结论

| 源码候选 | 普通GPU均值/P95 ms | 特殊夜间GPU均值/P95 ms | 相对已推送三层源码画质 |
|---|---:|---:|---|
| 已推送三层对照，同轮GT训练计时 | 0.2908 / 0.2957 | 0.2880 / 0.2893 | 对照 |
| 校准后的 GT 弱变化快速模型 | 0.1875 / 0.1937 | 0.1378 / 0.1398 | 普通约+0.70 dB；夜间约−0.48 dB，夜间需评审 |
| 校准后的保留前端均值模型，另一同轮 | 0.3350 / 0.3381 | 0.3294 / 0.3319 | PSNR约+0.002/+0.004 dB；弱窗口约+2.1%/−1.0% |
| 低分辨率16000步融合对照，另一同轮 | 0.1946 / 0.2029 | 0.1346 / 0.1368 | 夜间均值指标下降较小，普通弱窗口响应曾下降约30% |

GT快速模型相对其同轮对照，GPU均值降低约35.5%/52.2%。保留前端模型用于较稳的画质和NPU算子映射对照，GPU耗时增加；参考投影分拆、分组恢复和抖动方案的GPU也增加，均未冒充速度收益。

GPU为RTX5090，完整输入输出，torch.compile，关闭TF32/CUDA图，30次预热、3×200次逐次事件计时。输入生成/布局准备排除；模型内统计、参考、全尺寸输出和Cast计入。不能据此推算SS928耗时。原始时间样本、源码/编译差异见各speed.json。

## 画质边界

全序列测试180帧，GT只有原始分辨率。指标来自完整模型输出回缩及同一GT区域；特殊夜间GT评估区域为右侧192列，完整视频仍含整个网络输入。没有真实3倍GT、目标实例标注或夜间目标实例级保护证明。架构已参考本测试结果选择，属于非盲测。

两处普通弱变化窗口中，GT快速监督使响应损失从约30%/11%缩小至11.3%/4.4%；保留前端候选更接近旧版。旧版本身的响应约为GT的0.36/0.53，不能把保持旧版响应称为真实弱目标完全保护。量化压力检查表明快速候选部分8位权重设置明显损失SSIM；SDK偏置/激活/混合精度需另核对。压力检查不等同实际SDK量化。

## 输入处理与计时范围

本包使用冻结的既有模型输入契约，绝不将额外模型统计挪到输入转换脚本。普通数据读取为uint16，归一化后在网络外继承九帧动态场校正：前六帧中位数参考、全局/行/列残差中位数、σ=4高斯宽场减除（系数0.9）。该算法包含实质去噪计算，当前GPU计时未包含。服务器两线程CPU实测均值约352.6 ms，P95约385.6 ms；这是本服务器结果，不能推算板端耗时，也不能凭模型时间宣称整条处理链60帧/秒。

特殊数据的当前数据集读取结果为float32，动态校正标志为false；包内保留这个实际输入，未假装它是传感器uint16原始文件。其前序生成链需要部署侧核对。此处模型输入契约完整重现，不证明特殊数据前序处理开销为零。

输入读取、布局表示和主机传输另计；若目标包括上述实质场校正，必须将其必要耗时纳入整体目标，并进一步改写/训练验证。当前所有NPU达标结论均为未验证。两类序列180帧均已逐帧与冻结数据集重建结果逐值一致验证；校正算法、归一化、九帧索引、上下文和输入SHA均保存。

## 交付入口

- `DEPLOYMENT-PLAN.md`：两轮部署顺序、模型和探针怎么配对、需要返回的实际证据。
- `DEPLOYMENT-MATRIX.json`：每张图的SHA、输入输出shape/type、角色、精度证据和首轮优先级。
- `HANDOFF.md`：未解决问题、失败方案与下一步。
- `source_onnx/` 完整及小图；`probes/` 模块图；`reference_outputs/` 每个完整候选的真实输入匹配源码输出。
- `test_vectors/` 两个实际九帧输入；`calibration_inputs/` 每场景四个训练输入，不含GT；`sequence_inputs/` 180帧重建素材。
- `videos/` 整图视频；`logs/` 全部训练、导出和评估日志；`budget_audit/` 原始预算标签问题。
- `runtime/`、根目录模型权重、`body_models/`、`frozen_system_dependencies/` 为独立源码运行所需依赖。服务器路径只用于原实验脚本；`infer_release.py` 可用本包目录直接执行。

所有旧发布保留。使用test环境，禁止base。模型输出单位0..255，按图声明float16/float32解读，不能沿用旧0..1或uint8解释。先按SDK真实stride提取有效元素；本包不猜SDK布局。

```bash
python reconstruct_sequence.py --sequence sequence_inputs/ordinary --frame 20 --output frame20.npz
python convert_inputs_for_graph.py --npz frame20.npz --onnx source_onnx/ordinary_cal_preserve_mean6_body3_native4_alignpixel.onnx --output input20
python infer_release.py --scene ordinary --case cal_preserve_mean6_body3_native4_alignpixel --input test_vectors/ordinary_frame_20.npz --output own_output.npz
```

输入重建默认保留Float32；输入转换器再按各图声明选择Float32/Half。Float32接口不能使用已舍入为Half的输入代替匹配参考。

输入重建校验可能受NumPy/OpenCV跨平台算术影响；不一致时脚本报错，应查版本和算法，不可静默重标定。部署包压缩文件含模型、探针、工具、两个输入和少量首轮匹配参考，其他素材独立保存，各文件均低于GitHub100MiB限制。
