# SS928 九帧模型 v0.11：持续优化与板端定位图

日期：2026-09-28。目标为普通重噪声与特殊夜间两套模型：九帧 1024×1280 输入，模型内生成整张 3072×3840 灰度图；板端纯 NPU 推理均值及 P95 各不超过 16.7 毫秒，同时维持去噪、弱目标、同场景亮度与局部对比度稳定性。RAW 读取、主机与 NPU 数据交互不计入该目标。本版尚无 SS928 实测，不能宣称达到目标。

## 起点与本版改动

部署端 v0.9 的 `rows32` 完整 FP16 图同步均值/P95 为普通 **28.782/30.052 毫秒**、特殊夜间 **30.389/31.557 毫秒**。主要任务组：普通前端及主体 6.502、参考 5.673+3.238、整图布局 8.925、输出报告转换 3.623 毫秒；特殊夜间对应 9.170、4.914+2.915、8.907、3.746 毫秒。v0.9 的 `Round` 字节图回退 CPU，约 574/598 毫秒；`raw6` 曾出现硬件 execute500004，禁止在业务板自动复试。

本版完成以下完整模型变化：

1. **前端裁剪**：检查冻结权重并断言被删权重及偏置均为零。普通与夜间时间卷积由 16 通道裁为实际使用的 6 通道；夜间首层 32 个输出中后 12 个与末层对应输入均为零，裁为 20 通道。保留九帧输入及既有六帧均值、九帧差分逻辑。
2. **普通参考支路蒸馏**：三条参考金字塔支路中保留第 0、2 条，训练集上下文蒸馏 8000 步，只更新该参考支路。另训单支路备选，质量略降，只在板端速度压力下比较。
3. **整图输出**：先将 4 个相位作 `DepthToSpace`，再用固定形状的 `Expand` 或 `Tile` 完成三倍灰度铺排；整张输出仍在模型图内。去掉原版多段反卷积、重排与拼接，固定形状导出链另做化简。输出卷积原本算 16 通道后只取前 4 个；四通道版仅复制这 4 个权重与偏置。`Expand` 与 `Tile` 均提供完整可测图。
4. **字节输出诊断**：`QuantizeLinear` 图实现与同一 ONNX Runtime 后端的就近偶数舍入逐字节相同，避开已知慢速 `Round`。`Add(0.5)→Cast` 是另一种舍入规则，普通约 3.83%、夜间约 4.59% 像素高 1 级；夜间 PSNR 下降 0.016 dB，仅作诊断。`Tile` 后的该组合在 ONNX Runtime 对半值还有额外 1 级差异，不作首选。

## 数值核验与完整视频

普通第 20 帧、夜间第 60 帧的真实 3072×3840 完整输出：四通道 `Expand`/`Tile` 与同结构 16 通道 ONNX 图逐像素相同；固定形状化简前后逐像素相同；六个输出模块小图对相同随机完整特征逐像素相同。安全版与基线之间的差异主要来自普通参考支路蒸馏，夜间前端裁剪的固定帧最大差为 0.25 灰度。`QuantizeLinear` 完整图对源 FP16 图按相同后端舍入后逐字节相同。板端算子精度、回退及 PC 偏差尚未验证。

`videos/` 包含普通安全版 60 帧、普通单支路备选 60 帧、夜间安全版 120 帧的**完整画幅四栏视频**，依次为输入、GT、v0.9 基线和候选；附首/中/末帧整图及原生三倍画幅单帧。夜间视频的 GT 按已有标定数据展示，质量指标只统计上述有效区域。视频帧率用于观看，不代表采集帧率。

## 板端一次部署的判断顺序

1. 保留 v0.9 的 `rows32` 基线。先处理部署报告所述测试机 C 盘空间不足；不删旧业务文件。采用同一 SDK 和 `compile_mode=6`，沿用部署端现有参考 `Resize` 的 R1 兼容改写，记录每张图改写前后节点与校验值。
2. 先转换普通/夜间安全版 `Expand` 与 `Tile` 四通道完整 FP16 图。若其中一种产生 AICPU/CPU 回退，记录算子及任务后停止该候选的长测。比较 `output_micrographs/` 的基线、Expand、Tile 三图，单独定位完整输出布局与输出卷积的任务时间。原 16 通道静态图作为四通道收益对照。
3. 对无回退者与 `rows32` 使用同帧、同编译模式、50 次预热及至少 600 次同步测量，分别给出纯 NPU 均值/P95、任务数，以及前端主体、参考前尾、输出布局、Report 转换的逐任务时间。评估门槛是普通和夜间的均值、P95 均 ≤16.7 毫秒，并且质量通过；GPU 计时不作门槛。
4. 若 FP16 Report 仍占较长时间，单独试安全版 `QuantizeLinear` 字节图并检查 AICPU；它含完整输出的 FP16→FP32 Cast，可能抵消收益。`AddHalfCast` 只作速度诊断，要与板端同帧灰度差和夜间指标一起判断。若普通参考仍是主要瓶颈，再编译普通单支路备选，先审查弱运动和暗部画面。
5. 对领先者核对普通、夜间同帧 PC 与板端完整输出、四相位排列、亮度和局部对比度，并输出 60/120 连续帧视频。若仍超过目标，下一轮直接依据每组任务的新实测分配修改；尤其需要 `DepthToSpace`、`Expand`、`Tile`、参考 Resize/R1 与 Report 的 NPU/CPU 归属。

本地无法取得 SS928 SDK、R1 代码和板端运行图，因此现阶段不能继续有依据地选择最终板端布局，也不能给出可信的板端耗时预测。这一组完整图和输出模块图覆盖了当前可独立验证的主要结构改法，并把下一次板测需要区分的瓶颈拆开。
